## 排查 `uv run uvicorn main:app --reload` 报 DeclarativeBase ImportError

**报错**：`ImportError: cannot import name 'DeclarativeBase' from 'sqlalchemy.orm' (G:\Anaconda3\lib\site-packages\sqlalchemy\orm\__init__.py)`

**根因（已实测复现）**：环境跑串，不是代码问题。
1. `pyproject.toml` 从未声明 `uvicorn` 依赖 → `.venv` 里没有 uvicorn。
2. `uv run uvicorn` 在项目环境找不到该命令，**静默回退到 PATH**（无任何警告），命中 `G:\Anaconda3\Scripts\uvicorn.exe`。
3. 那个 uvicorn 跑在 **Anaconda Python 3.9.13** 上，其 site-packages 里的 SQLAlchemy 是 **1.4.39**；`DeclarativeBase` 是 2.0 才引入 → ImportError。

**关键环境事实（以后复用）**：
- 项目 `.venv` 正常：Python 3.12.14 + SQLAlchemy 2.1.3 + `include-system-site-packages = false`。
- 用户机器 PATH 里 `G:\Anaconda3`、`G:\Anaconda3\Scripts` 排很前 → 凡"项目环境缺命令"都会落到 Anaconda base，而 base 包很旧。
- 自查口诀：**报错栈出现 `G:\Anaconda3\lib\...` 就是跑串了**。
- 规避写法：`uv run python -m uvicorn main:app --reload`（不存在 PATH 回退）。

**已实施的修复**：`uv add "uvicorn[standard]"` → 装了 uvicorn 0.54.0，**改动了项目 `pyproject.toml` 与 `uv.lock`**。

**修完暴露的后续问题（原 main.py 仍有 3 处）**：
1. `mapped_column(DateTime, insert_default=func.now(), default=func.now())` → SQLAlchemy **2.1 起 `default` 与 `insert_default` 互斥，硬报错**（2.0 早期只是警告）。去掉 `insert_default` 即可。
2. **`app` 被赋值两次**：第 9 行 `app = FastAPI()`，第 203 行又 `app = FastAPI(lifespan=lifespan)` → 前面注册的路由全丢，实测只剩 4 条默认路由；修正后 15 条。这是最隐蔽的坑。
3. `mapped_column(float)` 用了内置类型，应传 `Float`。
4. （安全）第 164 行数据库密码明文硬编码。

**验证结果**：
- MySQL 8.0.33 在 `localhost:3306` 正常运行，账号 `baozi` / 库 `fastapi_first` 可连。
- 用修正版端到端启动成功：lifespan 建表 `book` 成功，`/`、`/query_parameter`、`/html`、`/exception/99`、`/test/test_list` 全部正确响应。

## 补充：create_tables 的调用时机与 create_all 语义（用户提问，已实测）

**用户问题**：create_tables 是不是每次启动都会调用？表已存在还会调用吗？会被再次创建吗？

**实测结论**：
- `lifespan` 的 startup 阶段每次启动都执行 → `create_tables()` **每次启动都会调用**。
  （`--reload` 下每次保存代码触发的重启也算一次完整启动。）
- 但 `Base.metadata.create_all()` 的 `checkfirst` **默认 True**：先发 `DESCRIBE <表>` 探测，
  表存在就**直接跳过**，不会重复建、不报错。
- 实测对比（echo=True 日志）：
  - 第 1 次启动（表不存在）：`SELECT DATABASE()` → `DESCRIBE fastapi_first.book` → `CREATE TABLE book (...)`
  - 第 2 次启动（表已存在）：`SELECT DATABASE()` → `DESCRIBE fastapi_first.book` —— **CREATE TABLE 出现 0 次**
- 数据安全：不删表、不清数据。表 `create_time` 仍是首次建表时间 2026-10-05 19:53:57，
  结构 7 列完好（id/bookname/author/price/publisher/create_time/update_time），行数 0。

**给项目留的关键坑（后续一定会踩）**：
`create_all` **只建表、不迁移表结构**。若给 `Book` 模型新增字段（如 `stock`），重启**不会**自动加列
（因为表已存在被 checkfirst 跳过），届时会报 `Unknown column 'book.stock'`。
开发期处理：`DROP TABLE book` 后重启重建；正式项目用 **Alembic** 做迁移。
