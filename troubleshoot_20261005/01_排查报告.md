# DeclarativeBase 导入失败 — 排查报告

- 项目：`D:\python_code\FastAPI_hello`
- 报错命令：`uv run uvicorn main:app --reload`
- 报错信息：`ImportError: cannot import name 'DeclarativeBase' from 'sqlalchemy.orm' (G:\Anaconda3\lib\site-packages\sqlalchemy\orm\__init__.py)`
- 排查日期：2026-10-05

---

## 一、一句话结论

**你的 uvicorn 根本不在项目虚拟环境里，uv 悄悄回退去用了 Anaconda 的 uvicorn，而 Anaconda 里的 SQLAlchemy 是 1.4.39 老版本。**

`DeclarativeBase` 是 SQLAlchemy **2.0** 才新增的 API（1.4 时代叫 `declarative_base()`）。
所以只要解释器落到 Anaconda，就必然报这个错 —— **跟你的代码写法无关，是环境跑串了。**

---

## 二、证据链（5 步，全部实测）

### 第 1 步：项目 `.venv` 其实完全正常


`.venv/pyvenv.cfg` 里 `include-system-site-packages = false`，环境是干净的、没被污染。

### 第 2 步：真凶 —— `.venv` 里压根没有 uvicorn

```
ls .venv/Scripts/          → 没有 uvicorn
ls .venv/Lib/site-packages/ → 没有 uvicorn
```

原始 `pyproject.toml` 的依赖只有三个：

**`uvicorn` 从来没被声明过。**

### 第 3 步：uv 找不到命令，就去 PATH 里捞

`uv run uvicorn ...` 的行为是：先在项目环境找 `uvicorn`；**找不到时不会报错，而是回退到系统 PATH 继续找**，且**不打印任何警告**。

PATH 里恰好有：

```
which -a uvicorn
→ /g/Anaconda3/Scripts/uvicorn      ← 命中的是它
```

（你的 PATH 里 `G:\Anaconda3`、`G:\Anaconda3\Scripts` 都排在很前面。）

### 第 4 步：Anaconda 的 SQLAlchemy 是 1.4.39，没有 DeclarativeBase

```
G:\Anaconda3\python.exe                    → Python 3.9.13
G:\Anaconda3\lib\site-packages\sqlalchemy\__init__.py
    __version__ = "1.4.39"
grep -c "DeclarativeBase" .../orm/__init__.py → 0    ← 完全没有这个名字
```

### 第 5 步：报错栈自证

```
Process SpawnProcess-1:
  File "G:\Anaconda3\lib\multiprocessing\process.py" ...      ← Python 3.9 的 stdlib
  File "G:\Anaconda3\lib\site-packages\uvicorn\_subprocess.py"
  File "G:\Anaconda3\lib\site-packages\uvicorn\server.py"
```

栈里的 `G:\Anaconda3\lib\...` 说明：**跑起来的解释器是 Anaconda 的 Python 3.9，不是你的 3.12。**
`main.py`（你的代码）被 Anaconda 的 Python 加载，它去 Anaconda 的 site-packages 找 SQLAlchemy，找到 1.4.39，于是崩了。

## 四、根因解除后，又暴露出 3 个本来被压住的坑

修完第 1 个错误，再启动时会依次遇到下面这些（我已按顺序实测）：

### 坑 1 — SQLAlchemy 2.1 起 `default` 与 `insert_default` 互斥（硬报错）

```
sqlalchemy.exc.ArgumentError:
The 'default' and 'insert_default' parameters of Column are mutually exclusive
  File "D:\...\main.py", line 175, in Base
    create_time: Mapped[datetime] = mapped_column(DateTime, insert_default=func.now(), default=func.now, ...)
```

你两个都传了。**去掉 `insert_default=func.now()` 即可**，`default=func.now()` 本身就只在 INSERT 时生效，效果一样：

```python
create_time: Mapped[datetime] = mapped_column(DateTime, default=func.now(), comment="创建时间")
update_time: Mapped[datetime] = mapped_column(DateTime, default=func.now(), onupdate=func.now(), comment="更新时间")
```

> 这也是个"版本陷阱"：这个写法在 SQLAlchemy 2.0 早期只是警告，2.1 变成了报错。
> 你的 `pyproject.toml` 写的是 `sqlalchemy[asyncio]>=2.0`，uv 解析到了 **2.1.3**。

### 坑 2 — `app` 被赋值两次，前面注册的路由全丢了（最隐蔽）

```python
# main.py 第 9 行
app = FastAPI()

# ...中间注册了 /async /sync /html /news 等一大堆路由...

# main.py 第 203 行 ← 又赋了一次值，上面那个 app 连同它的路由一起被丢弃
app = FastAPI(lifespan=lifespan)
```

结果：服务能启动，但你访问 `/async`、`/sync`、`/register` 全是 **404**，只有 `/docs`、`/openapi.json` 存在。

**实测对比：**

| 版本 | 注册路由数 |
|---|---|
| 原 `main.py` | 4（仅 docs 等默认路由） |
| 修正后 | **15**（含 `/async` `/sync` `/register` `/html` `/file` `/news/{id}` `/exception/{id}` `/test/test_list` 等） |

正确做法：`app` 只创建一次。把 `lifespan` 定义挪到前面，直接一次成型：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    await create_tables()
    yield
    await async_engine.dispose()

app = FastAPI(lifespan=lifespan)   # 只在这里创建，之后不再赋值
# 路由装饰器写在下面
```

### 坑 3 — `mapped_column(float)` 用了内置类型

```python
price: Mapped[float] = mapped_column(float, comment="价格")   # 传的是 Python 内置 float
```

应传 SQLAlchemy 的 `Float`：

```python
from sqlalchemy import Float
price: Mapped[float] = mapped_column(Float, comment="价格")
```

## 六、以后怎么避免同类问题

**1. 只声明依赖不够，服务器程序要把 uvicorn 一起声明。**
`fastapi` 不会自动带 `uvicorn`。建项目时就该写：

```bash
uv add "fastapi" "uvicorn[standard]" "sqlalchemy[asyncio]" "aiomysql"
```

**2. 让 VSCode 也明确认准 `.venv`。**
你的 `.vscode/settings.json` 目前只有：

```json
{ "python-envs.defaultEnvManager": "ms-python.python:venv" }
```

建议补上解释器路径，避免编辑器和终端各跑各的：

```json
{
    "python-envs.defaultEnvManager": "ms-python.python:venv",
    "python.defaultInterpreterPath": "D:\\python_code\\FastAPI_hello\\.venv\\Scripts\\python.exe"
}
```

以及：`Ctrl+Shift+P` → **Python: Select Interpreter** → 选带 `.venv` 的那个。

**3. 警惕 PATH 里的 Anaconda base。**
你的 PATH 里 `G:\Anaconda3` 排得很靠前。任何"项目环境里没装"的命令，都会静默落到 Anaconda base 上，而 base 里的包版本往往很旧（比如这里的 SQLAlchemy 1.4.39）。
自查一句话：**报错栈里出现 `G:\Anaconda3\lib\...`，就说明跑串了，不是代码问题。**

**4. 用 `uv run python -m xxx` 而不是裸命令。**
`uv run python -m uvicorn main:app --reload` 会强制使用项目解释器，不存在 PATH 回退，更安全。
